### 0.4 ⚠ C-005 暂停前已产出的实测结果（留档，不得丢弃）

暂停不等于作废。实施生成器时已跑出三条**此前未知**的结果，均已同步进设计说明
（v1.2 修订记录）与生成器注释：

**（1）设计说明的三处实测纠正**（初稿是错的）

| # | 初稿 | 实测 |
|---|---|---|
| ① | "盒式平均下灰度**恰好**等于亮面积占比"，`ss ≥ 8` | 硬阈值超采样把灰度量化到 `n/ss`（实测只取 255 的 1/8 步长）→ **渲染量化 = `1/ss` px**。`ss=8`（0.125 px）对 Baseline 够用，对 0.1~0.2 px 目标**不够**，须 `≥ 64` |
| ② | V-3 用 `t=0.0` vs `t=0.5` 比"应同图" | `t=0.0` 触发边界取整的**端点效应**，按初稿写会**误判超采样未生效**。改为"同一整数格内须同图 / 跨格须不同" |
| ③ | 棋盘格周期 40 px | 四个结构点**全被剔除**，`maxResidualPx = 39.999`（恰等于周期）—— 同族相邻边界梯度方向相同，被倍角聚类并成一组。改 1000 px |

**（2）`ss` 敏感性的决定性实验**

`ss = 8 / 16 / 32 / 64` 在四个相位的读数**逐位相同**（199.0 @ p=0，200.0 @ p≥0.1）。
两个含义：该量级的测量**不受渲染量化限制**；**1 px 量化确实不是渲染造成的**，
而是 `Canny` 整数边缘图 + `fitLine` 的实现行为。

**（3）⚠ 新发现：θ ≥ 30° 时结构点被全部剔除，`cad_assisted` 静默转 false**

| θ | 偏差 | `maxResidualPx` | `available` | 卡在哪一步 |
|---|---|---|---|---|
| 0° | −1.0 → −0.9（阶梯，整数量化） | **0.000** | ✅ | — |
| 15° | **−0.503 恒定**，读数随相位连续 | 0.248 | ✅ | — |
| 30° | 无读数 | **0.342** | ❌ | `matched=4, rejected=4` |
| 45° | 无读数（p=0.9 例外成功） | 0.707 → 0.240 | ❌ | 同上 |

⚠ **`projected=4, matched=4` 在所有角度都成立** —— 投影与梯度分组**从未失败**，
θ ≥ 30° 的失败**纯粹是冻结的 0.3 px 残差判据**造成的。

后果（`CadStructureLocator.h:82-84`）：`available=false` → 调用方退化为纯 A 类、
`cad_assisted` 记为不满足项 —— **不报错**。即 **B 类在对角棱线上整个不可用，系统只安静降级**。
θ=30° 的 0.342 只比判据高 **15%**，是一道**悬崖**。

**保留的疑点（013 阶段必须先解决）**：这是**理想合成图**（无噪声/模糊/压缩）上的结果，
实机只会更差；`maxResidualPx` 这个字段名与它实际持有的量不符（README §6 第 42 行：
实现取的是**中位数**）；以及它是否部分源自旋转棋盘格构造，需一个单边对（非棋盘格）对照来分离。

**（4）生成器本身的状态**

`SyntheticEdgeGenerator` 已编译通过、并被上述实验实际驱动；`ss` 不自动选（口径必须可见）；
`ss < 8` 当场抛异常。**这是可复用的资产，013 阶段直接接上 `SubPixelMethods` 即可。**

### 3.1 `cam*.json` 逐路元数据（前置 A）

现状：`config/` 只有 7 个 yaml，**不存在任何 `cam*.json`**。

需要定义并落盘的逐路字段：

在只有 CAM25 真实接入的当前阶段，这条会**逼迫为两台不存在的相机伪造元数据**

| # | 规则 |

## §4 011-A1：`ImvCameraBackend` 实现（评审新编号；原题「011-B」）

### 4.1 它是"填桩"，不是"从零设计"

`ImvCameraBackend.h` 已经把设计决定写死了，实施时**必须遵守**：

| 已冻结的决定 | 出处 |
|---|---|
| **单一类，三个实例**（不是三个类） | `.h:29-37`：SYS-06 §7 的"三个实例"指实例数；ENG-09 §4.3 的冻结类清单只有 `ImvCameraBackend` 一个类 |
| **SDK 类型不进头文件**，句柄保持 `void*` | `.h`：本头文件被 device 层其它文件包含，include SDK 头会让**整个 device 模块**依赖可选的 SDK —— SDK 缺失时连虚拟相机都编译不了 |
| **不使用 `config_.width/height` 作为回退** | `.h:57-62`：画幅由设备回报，配置值只用于**比对**（内参矩阵按标定分辨率标定） |
| **不"假装成功"** | `.h:19-25`：`initialize()` 返回 true 却不真正采集，会让可用相机数虚高为 3、降级判据失效 —— "返回 false 使'这台相机不可用'成为**唯一且真实**的事实" |

### 4.2 实现要求（来自 `ICameraBackend.h` 的契约）

- `grab()` 必须填满 **7 个字段**：`image` / `frameId` / `timestampNs` / `deviceTimestampNs` / `cameraId` / `role` / `exposureTime`；
- ⚠ `timestampNs` **必须取主机 `CLOCK_MONOTONIC`**，**禁止墙钟** —— 墙钟受 NTP 阶跃影响，
  会制造虚假同步偏差，而三相机同步判据正建立在此字段上（`ICameraBackend.h` 的说明）；
  `data/MonotonicClock.h` 已存在，直接用；
- `frameId` **必须单调**（前置 B）；
- `stop()` 允许在未 `start()` 时调用且**无副作用**；
- 实现**不负责线程安全**（每个 backend 归其所属设备线程独占，SYS-09 §3/§14）。

### 4.3 验收

⚠ **本节是提要，逐项可勾选、可留证的验收台账见**
**[《011-A1_A7A20MU201单相机接入验收清单》](011-A1_A7A20MU201单相机接入验收清单.md)** ——
