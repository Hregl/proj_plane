## 2 证据类别：按**覆盖哪段路径**划分，不排"强弱顺序"

> ⚠ 早先的写法把"后端直连"称为"强度**介于** SDK 探针与应用实际装配之间"，
> **该表述已删除**：证据类别应按**覆盖范围**读，而不是排成一条统一强弱序列 ——
> 覆盖面不同、互不蕴含，谁也替代不了谁。

| 类别 | **覆盖到哪一段** | **没有覆盖哪一段** |
|---|---|---|
| **OS 枚举**（01） | 内核／USB 栈：设备存在、被识别、接口形态（USB3 Vision） | SDK、本项目的后端与配置、能否打开与取帧 |
| **SDK 探针**（本批未采） | SDK 与驱动、设备协同（用 SDK 自带样例） | 本项目后端、配置、错误分类、装配边界 |
| **后端直连（专项验证工具）**（04） | **真实 `ImvCameraBackend` → `ImageFrame` → 生产版 `Recorder::save()`** 的字节保真与解码 | **应用装配**（配置装载、装配点、状态机、控制器、业务触发）；**它不是一次测量** |
| **应用实际装配**（02、03） | 配置装载／装配／状态机流转／失败边界在真机上成立 | **RAW 字节保真**（失败包按 C-007 不带原图，本批**没有**应用路径产出的 `.raw` 可比对） |

**两条使用纪律**（与验收清单 §1 一致）：

1. 第 1~6 项**不得**用"后端直连"整项通过 —— 它可以**支撑其中的子判据**
   （例如第 4 项的"设备实际格式／位深／总字节数"、第 8 项的"保存与解码保真"），
   但**不能**代替"应用装配路径"上的记录；
2. **应用失败包**（03／05）能说明状态流转到过哪里，**不能**证明 RAW 字节保真
   —— 包里 `data_source` 是 `none`、没有 `.raw`。
