快照只为本次实机验证存在。出厂内网 IP 不进入版本库。

2 直接启动（实机地址，headless）
------------------------------------------------------------

命令（在 AircraftPoseSystem 下；配置目录为仓库外快照）：

    QT_QPA_PLATFORM=offscreen timeout --signal=TERM --kill-after=5 25 \
        build/AircraftPoseSystem <配置目录>

2.1 第一次尝试：相机条件导致启动失败
    快照中的 camera.yaml 仍保留现场取值（cam25 为 imv 后端）。
    启动在相机打开阶段失败，退出码 1，报错明确拒绝回落：

        通道 cam25 在设备打开检查时不可用 …… 已枚举到 0 台设备
        本程序不会用其它通道或虚拟后端来让本次启动看起来成功

    该失败**不是**转台装配失败，而是相机不在位。如实记录，
    未重试、未伪造通过。

2.2 第二次尝试：仅把快照中的相机改为全虚拟
    为了隔离转台装配，**只改仓库外快照**的 camera.yaml：
    cam25 的 backend 由 "imv" 改为 "virtual"、serial 置空。
    原始 imv 版本保留为 config_snapshot/camera.yaml.with_imv。

    启动结果：装配成功，日志包含

        设备：触发已使能、转台已就绪
        装配完成：MeasurementController 已就绪，等待 startMeasurement()
        启动完成，共 17 条告警

    应用运行到 25 s 被 timeout 的 SIGTERM 终止，退出码 **124**。
    124 表示“超时终止”，**不是应用正常退出**；未执行正常析构路径。
    日志中的 17 条告警为既有的配置默认值/合成标定/机型库缺失告警，
    与转台无关；机型库缺失只影响 POSE_SOLVE，且本次未启动测量。

2.3 界面角度核对：未执行
    当前环境为 headless（QT_QPA_PLATFORM=offscreen），
    本机没有 Xvfb / xwd / import / scrot 等可用的虚拟显示与截图工具，
    因此**没有**对界面上的转台角做目视或截图核对。
    这一项如实登记为“未执行”，不用推断代替观察。

3 生产后端只读读数（替代性核对）
------------------------------------------------------------

用**同一份生产代码** PelcoDTurntableController（不是测试桩）
编译独立探针，不调用 move()：

    g++ -std=c++17 -O2 -I src probe_backend.cpp \
        build/lib/libdevice_turntable.a build/lib/libdata.a \
        -lpthread -o /tmp/readonly_backend_probe
    /tmp/readonly_backend_probe <设备地址> 6666 1

结果（退出码 0）：

    initialize... INIT_OK
    STATE t=200ms  az=4.67 el=-14.51 motion=0 (IDLE)
    STATE t=400ms  az=4.67 el=-14.51 motion=0
    ...
    STATE t=1600ms az=4.67 el=-14.51 motion=0
    DESTROY...

与纯探针（02）的 4.68 / -14.51 相比：
    水平差 0.01 deg，垂直差 0.00 deg，
    均在编码器 0.01 deg 量化与 0.05 deg 停止条件之内。

结论：应用的转台后端在实机上能初始化并持续读到正确角度；
但因 2.3 的限制，**不以本项代替界面核对**，两者分别登记。

4 线缆级只读证明（本机 UDP 中继）
------------------------------------------------------------

中继只做原样转发：应用/探针发往 127.0.0.1:6666，中继转发到设备，
再把设备回复原样回传；中继不构造、不修改、不注入任何报文。
快照 config_snapshot_loopback/ 仅把 host 改为 127.0.0.1。

4.1 生产后端探针经中继运行
    持续时间约 2 s，探针正常退出（exit=0，含析构）。
    抓到的应用→设备帧共 57 帧：

        0x51 水平查询     x28
        0x53 垂直查询     x28
        0xE0 工作模式查询 x1

    控制帧（0x4B/0x4D/0x00）：0

4.2 完整应用经中继运行
    应用以全虚拟相机 + pelco_d_udp 启动，运行 12 s 后由 timeout 终止
    （退出码 124；同样未执行正常析构）。
    抓到的应用→设备帧共 401 帧：

        0x51 水平查询     x200
        0x53 垂直查询     x200
        0xE0 工作模式查询 x1

    控制帧（0x4B/0x4D/0x00）：0

4.3 “退出时未发送停止帧”的口径
    4.1 的探针走完了正常析构路径（DESTROY + exit=0），
    说明**空闲状态下的析构不会发送停止帧**。
    4.2 的应用是被 SIGTERM 终止的，未走正常析构路径，
    因此不能据此断言“应用正常退出时如何”；该口径由 4.1 单独证明。
    两条运行期间均无控制帧，与“本批从未调用 move()”一致。

------------------------------------------------------------
5 工作模式回包的已知限制
------------------------------------------------------------

0xE0 查询帧与收到的回包逐字节相同，无法区分“设备回复 0x00”
与“原样回显”。详见 02_探针实测_只读.txt 第 4.2 节。
本记录不据此断言“已独立证实设备工作模式为 0x00”。
