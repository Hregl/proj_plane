# 本批两处修复的定向变异检查（先红后绿）

基线：本工作树 `feat/turntable-control` + 本批未提交修改（两处修复 + 测试 +
契约同步）。构建：`build-dev`，被测目标 `test_turntable_control_service`、
`test_system_initializer`。

规则：先把修复**改回错误实现**，确认预期断言变红；再恢复源码（**用编辑恢复，
未使用文件复制恢复**），确认同一用例转绿、正常对照仍绿。全部恢复后核对：
三处源码 `sha256sum -c` 成功，且 `git diff` 与变异前快照逐字相同
（`diff -q` 无差异），随后整套 40 例 100% 通过（见 `08_定向测试_40_40.txt`）。

## 变异与结果

| # | 修复 | 变异（改回错误实现） | 期望断言（反例） | 实测 |
|---|---|---|---|---|
| M1 | 到位须同时满足“本条命令已交付 + STABLE + 容差内” | 到位判据删去 `commandDelivered_ &&`：`if (commandActive_ && state.motion == STABLE && inTolerance)` | `TurntableControlServiceTest.排队中的新命令不得借用上一条STABLE提前到位` | **红**：`queued.positioningEnabled` = true（应 false，定位未被互斥挡住）；`requestMove()` 返回 true（应 false）；错误串无“上一条定位尚未结束”；等待 `Stage::Delivered` 超时 3000 ms——排队中的新命令被上一条的 STABLE 直接判到位。正常对照 `定位按受理交付到位推进并可连续操作` **仍绿** |
| M2 | 退出清理仅在“当前事务尚无停止请求”时调用公开 `stop()` | `turntableNeedsShutdownStop()` 内把 `stopBelongsToCurrentMotion` 置为恒 false（等价于内部退出永远调用公开 `stop()`） | `SystemInitializerTest.场景A3b_退出清理不把自身当成新的外部停止请求`、`场景A3d_退出清理不重新武装已耗尽的停止预算` | **红 ×2**：A3d `turntableNeedsShutdownStop()` 返回 true（应 false，“当前事务已有停止结果，内部退出不应再调用公开 stop()”）；`fake->stopSendAttempts` = **6**（应 3）——退出清理把已耗尽的停止预算重新武装。正常对照 `场景A3c_退出清理仍收口尚未停止的活动命令`、`场景A3e_退出清理收口真实控制器的活动命令` **仍绿** |
| M3 | 同上 | `turntableNeedsShutdownStop()` 直接 `return false`（等价于内部退出永不收口活动命令） | `场景A3c_退出清理仍收口尚未停止的活动命令`、`场景A3e_退出清理收口真实控制器的活动命令` | **红 ×2**：A3c 停止调用次数 = 0（应 1）；A3e 真实控制器的活动命令未被收口（断言 false，应 true）。正常对照 `场景A3b`、`场景A3d` **仍绿** |

判读：

* M1 与 M2/M3 是**互不替代的两层**：前者管“到位归属”（界面不得借用上一条
  命令的稳定读数），后者管“退出清理不得重新武装已耗尽的停止预算，且不得
  漏掉尚未停止的活动命令”。M2 与 M3 是同一判据的两个方向（恒真/恒假），
  两侧都有独立反例，因此既不能靠“总是调用 stop()”也不能靠“总是不调用”
  蒙过去。
* M2 的 6 次 = 用户停止路径 3 次（1 首发 + 2 重试，预算已耗尽）+ 退出清理再
  3 次；这正是评审指出的缺陷形态，恢复后为 3。
* M3 的首次变异写法（`true || (...)`）**编译失败**，随即改用 `(void)…; return
  false;`；编译失败的那次运行输出使用的是上一次产物（M2 二进制），**其
  结果未被采信、未写入上表**，上表 M3 行来自重新编译后的产物。
