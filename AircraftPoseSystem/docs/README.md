# docs/ —— 设计文档目录

本目录按 **ENG-01 §3.1** 预留，**当前为空**，且**刻意不存放设计文档副本**。

## 为什么不放副本

本项目的 22 份设计文档（SYS-01~SYS-15、ENG-01~ENG-10）位于本代码仓库**之外**：

```
../项目文档/
├── 系统设计/      SYS-01 ~ SYS-15
├── 软件工程设计/  ENG-01 ~ ENG-10
├── 编码实现/      （空）
├── 部署交付/      （空）
└── 测试验收/      （空）
```

同一份文档存在两处副本时，必然出现"改了一处忘了另一处"，而本项目是
**文档先行的纯设计工程**——ENG-09《类型与命名冻结表》是类型与命名的
唯一权威，ENG-03 是 CMake 的唯一权威。副本分叉会让"以哪一份为准"
无从判断，代码与文档的对应关系随之失效。

因此：**文档只在 `../项目文档/` 维护，本目录不做镜像。**

## ENG-01 §3.1 的子目录规划

ENG-01 §3.1 规划了 `docs/{system,interface,algorithm,engineering,test,deployment}`。
该规划对应的实际位置如下（保持一一对应，避免将来重复建档）：

| ENG-01 §3.1 | 实际位置 |
|---|---|
| `docs/system/`       | `../项目文档/系统设计/` |
| `docs/interface/`    | `../项目文档/系统设计/SYS-04_接口控制文件ICD_*.md` |
| `docs/algorithm/`    | `../项目文档/系统设计/SYS-07_*`、`SYS-12_*`、`SYS-14_*` |
| `docs/engineering/`  | `../项目文档/软件工程设计/` |
| `docs/test/`         | `../项目文档/系统设计/SYS-15_*`、`../项目文档/软件工程设计/ENG-06_*` |
| `docs/deployment/`   | `../项目文档/部署交付/` |

## 本目录将来的用途

仅在需要**与代码同生命周期**的文档时才启用，例如：

- 自动生成的 API 文档（Doxygen 输出，已在 `.gitignore` 中排除 `doc/html/`）；
- 构建说明、现场部署 Checklist 等不进入设计基线的操作类文档。

凡进入 `../项目文档/` 的文档，**不得**在本目录建立第二份。
