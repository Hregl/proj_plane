    +

## 2.1 本地仓库是唯一权威源

本地Git仓库是**唯一权威源**。远端仓库（无论自建还是公网私有仓库）只作**备份与协作通道**，
**不是交付判据** —— §19 的六条验收标准全部以本地仓库为准。

因此"有远端"不能替代"有本地仓库"，更不能替代"有离线备份"。

## 2.2 远端仓库（V2.2 修订，裁决 C-012）

⚠ **本条取代 V2.1 原文。**

V2.1 原文（**已被取代，保留备查**）：

> 不依赖：
>
> -   公网GitHub；
> -   公网GitLab；
> -   云同步。

**C-012 裁决（2026-09-24）：解除上述一概禁止，允许使用公网私有仓库作远端。**
修订后的约束是：

1. **远端仓库必须是私有的** —— 不得为公开（public）仓库；
2. **远端不得是唯一副本** —— 本地仓库 + 离线备份仍是必备项，不因接入远端而豁免；
3. **推送前必须完成清理** —— 见 §2.3；
4. ⚠ **§18 涉密环境约束未被本条解除**，且是**独立闸门**：C-012 只解除了
   "公网托管平台一律禁止"这一条，**不等于**允许把涉密内容推送到公网。
   推送前须先按 §18 确认该内容不涉密或已获批准。

## 2.3 推送前的清理要求

推送到公网远端之前，必须确认版本库中**不含**：

| # | 项 | 理由 |
|---|---|---|
| 1 | **内网 IP / 网段** | 暴露内部网络拓扑 |
| 2 | **本机绝对路径** | 暴露开发机目录结构，且含用户名；换机器后亦无意义 |
| 3 | **凭据**（口令 / Token / 私钥 / 证书） | 直接的安全事故 |
| 4 | **厂商 SDK 分发物** | 授权 / 厂商文件 / 平台绑定，见 §3 与 `third_party/README.md` |
| 5 | **构建产物** | 见 §3，且体积大 |

⚠ 清理必须作用于**整个版本库的历史**，而不只是当前工作区 ——
一个提交之后才发现的问题，清理成本远高于提交前 `grep` 一遍。

## 21.1 本版变动说明

**本版只解除了"用什么平台托管"这一条约束，没有放宽"什么内容可以出门"。**

1. **§2.2 修订** —— V2.1 的"不依赖公网GitHub / 公网GitLab / 云同步"经 **C-012** 裁决解除，
   改为允许公网私有仓库作远端，并加三条约束（**必须私有** / **不得是唯一副本** / **推送前清理**）。

3. **§2.3 新增** —— 推送前的清理清单。项目此前无版本管理仓库，本条无从谈起。
4. **§18 补注** —— 明确 §18 **未被解除**，且与 §2.2 是**两道独立闸门**。
   ⚠ 这一点必须在同一份文档里写清：否则"§2 已解除禁止"会被读成"可以往外推"。
